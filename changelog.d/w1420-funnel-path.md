- **The portal VM watch no longer blames the tailnet policy for Funnel outages, and repairs them** (w1420, asked by Ben): layer 7 counts a Funnel server's SYN to the node's own peer API port as a hand-off (tailscaled logs it "Drop: ... no rules matched" and then accepts it), so the urgent "grant tag:ingress → tag:fff-portal" alert no longer fires on every outage; Funnel needs no such grant (RUNBOOK corrected). Layer 9's line now says, for each failing Funnel server address, its curl code, whether the failing requests reached tailscaled (`peerapi_ingress`), how many Funnel servers have a fresh handshake, and tailscaled's control and link lines of the last 15 minutes; after 3 failing passes it sends the Funnel registration again (`tailscale funnel reset`, the same serve config back) and after 10 restarts tailscaled, once per outage (tailscale/tailscale#21114). `portal_logs` gains a `tailscaled` source. The host side needs `git -C ~/ff-factory pull && sudo ~/ff-factory/deploy/vm/host/install.sh --host-only --yes` on the FFBox host; the portal side a portal deploy.

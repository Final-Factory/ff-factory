- **A worker whose request asks for work in a machine's main clone may quit its editor, back up, fetch, check out and reopen Unity there** (w936, Ben: "I fucking built ff factory. It's my call"). The guard refused every command naming a main clone (`protectedPaths`), so w934's worker could not close the editor open on Ben's m5 clone or check the connector branch out, whatever the prompt said. A request now takes `main_clone: "<machine id>"` (`request_work`, or `update_work` later; `false` takes it back): a field on the request, set only by its person's own orchestrator in a turn of theirs, never on an intake request and never by text in a brief. A worker on that machine serving it gets `guard.mainClone` with each message, and `server/mainCloneGuard.ts` then judges each command that names the clone: allowed are the bridge's save-scenes-and-`EditorApplication.Exit(0)` snippet, `git stash list/push/save/create/store/show`, `git branch <new>`, `git diff > <file outside the clone>`, `git fetch` (no prune or force), `git checkout`/`switch` of a branch (no `-f`, `-B`, `--`, paths), `merge`/`pull --ff-only`, read-only git, `Unity -projectPath <clone>` to reopen it, and `grep`/`pgrep` for its editor, always as `git -C <clone>` (no `cd`). Deletes, reset, clean, restore, stash pop/drop, push, redirects into the clone, Write/Edit and every other protected path stay refused, with a refusal that lists the allowed forms. The worker brief carries the list; the orchestrator and dispatcher prompts say when to set the grant. Needs a portal deploy, and the machines' daemons at this version (an older one ignores the field and refuses as before). docs/orchestrators.md "Work in a machine's main clone".

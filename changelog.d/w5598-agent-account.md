- **The portal's agents run as their own OS account** (w5598): the orchestrators, the dispatcher and the bug-thread judge start as `fff-agent` through `fff-agent.socket` (`deploy/vm/guest/fff-agent-launch`, `fff-agent@.service`), which can open no `/proc` of the portal's account, so neither the portal's memory nor its git and gh's `GH_TOKEN` are open to them; they see the portal's folders through idmapped views (`fff-agent-views`), so their transcripts and memory stay the portal's files. Any failure before the launcher's OK starts that agent as before and alerts the owners; two failed agents in 30 minutes switch them all back; config `agentAccount` `"off"` (set_app_config) does it at once. `fffctl fence-check` probes as `fff-agent` too, with a stand-in git child ([docs/vault.md](../docs/vault.md)). Needs a portal deploy.

- **A worker's Unity Library copies stay under 40 GB** (w3674): one running worker ran `scratch_clone.sh --library` four times in 50 minutes, each copy a whole 33.9 GB Library, and F: on BEAST went from about 99 GB free to 0, because the clean-up never takes a running worker's Library. Now, on every clean-up pass, a worker's Library folders over 40 GB (`libraryCopyCapGB`) together lose the oldest idle ones, whole, unless a process names the project, anything in the Library was written in the last 15 minutes, or git holds the clone's work tree. The next build or editor start reimports what goes.

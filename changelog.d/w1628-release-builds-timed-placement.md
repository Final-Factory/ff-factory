- **Only release builds go to BEAST first** (w1628; lothsahn: "Ben's guidance was only supposed to be for release builds of the software, not all builds that workers do when making fixes"): `build_plan` plans a release build only (`release: true`); a worker's own player build (a fix, a clip, a playtest) builds where it is, clears nothing and gets no BEAST preference. A release build passes over a computer with a timed leg running or waiting in its bench queue (lothsahn: "Yes, let's make the change you recommend to move things off when there are timed runs"), which each daemon now reports. [docs/orchestrators.md](docs/orchestrators.md), "Builds clear BEAST".
- **Timed work goes to small computers first, BEAST last** (w1628; lothsahn: "We should also prefer boxes with a small number of slots and players for timed runs, not beast since it's big"): the Capacity block's "Next timed work" picks, on the platform the work names, a computer with no timed leg queued, then the smallest. [docs/orchestrators.md](docs/orchestrators.md), "Timed work goes to small computers first".
- **The bench queue follows request priority** (w1628; lothsahn: "Yes, the queue should first sort by priority"): the portal sends each daemon its workers' request priorities every minute, written where the game repo's bench queue reads them; editor-gate tickets carry the worker's session. [docs/unity-lifecycle.md](docs/unity-lifecycle.md), "The bench queue".

- **A token's last usage reading survives a restart and a failed poll** (w1041, lothsahn: "Please fix it so the portal persists the token usage somewhere so it can read the last value on startup."). After the 2026-10-11 deploy the first poll got a 429 and no network, a failed poll overwrote the saved reading with "unknown", and the pool counted 50% on both windows: inside the dispatcher's reserve, so new work (w1038) waited. A failed poll now keeps the token's own last reading (not after a 401); the scheduler and `system_status` use it aged: a window past its reset time counts 0%, a reading older than 6 hours counts at least 50% in windows not yet reset, and a reading not taken by this process is labelled "persisted reading ... read N min ago". The endpoint's 429 Retry-After and 403 refusals are persisted in `data/usage.json` too. The 403 on the usage endpoint is expected for `claude setup-token` tokens (no `user:profile` scope); the rate-limit headers answer for them (docs/vault.md 4a). **Needs lothsahn's portal deploy.**

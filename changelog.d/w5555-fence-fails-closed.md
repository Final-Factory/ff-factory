- **The worker fence fails closed, with a portal alert (w5555, lothsahn):** when daemon.json turns this OS's worker fence on (Seatbelt, Landlock or Windows Low integrity) and its setup or probe fails, the daemon no longer runs sandbox workers unfenced: it refuses their starts with the probe's error, the portal shows a red banner on the machine and alerts the orchestrator and the host's devices once, naming the machine and the error, and placement counts the machine busy (`worker fence failed: ...`) so requests go elsewhere. While the fence is still being set up after a daemon start, a worker's start waits for it. A fence switched off on purpose (`ops_worker machine_update worker_fence off`) starts workers unfenced as before. Standing agents, the ops worker and orchestrators run outside the fence on purpose and are never held. [docs/worker-root.md](docs/worker-root.md) 4.3 "When the fence fails".

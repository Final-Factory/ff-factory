- **FFU builds stop refilling worker disks, and git noise no longer keeps a clone** (w3330, asked by Ben): a stopped worker's Rust build folders (a folder cargo tagged with its `CACHEDIR.TAG`, such as the ffu-build-test skill's `$TMPDIR/ffu-target`, 15.4 GB in one worker on LothDesktop) now go with its other rebuildable caches (after 24 h idle, or 15 min while disk is low; never a live worker's). A release rebuild costs about 1 min 40 s (client) and 31 s (headless). A shared target was ruled out: two builds on one target wait on cargo's lock (measured). `localWorkWhy` (ff-leftovers, the sweeps) now counts only real changes: a file git status flags but `git diff HEAD --ignore-cr-at-eol` shows unchanged (a line-ending-only rewrite, or an LFS file whose index still records the pointer's size) is no longer uncommitted work, so such a clone shows `DELETE`; an untracked file, a deleted file or a real edit still keeps it.

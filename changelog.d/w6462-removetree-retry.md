- Removing a folder on Windows now makes sure it is gone. `rd /s /q` answers success and leaves entries named `x.`, `y ` or `NUL` in place, with everything in them (measured on LothDesktop). When the folder is still there after rd, the daemon runs rd again by the folder's `\\?\` path, which removes them, and removes a junction inside them without touching its target (measured). A folder whose own name ends in a dot or a space goes by its `\\?\` path at once. A folder still there after every try is reported as a failed remove, with a line saying so. lockIn's own retry (w6437) is gone, since it uses the same remove (w6462).

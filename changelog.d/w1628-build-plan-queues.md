- **A planned build no longer waits for a free bench lock** (w1628, asked by lothsahn: "How can we make the workers more parallel?"): `build_plan start` says `Go` while a timed run holds the machine's bench lock, with a note that the build's own Unity run takes a shared ticket in the bench queue (w1615) and starts as soon as that leg and any queued before it end, never beside one. Polling for a free lock lost: BEAST's lock was free for at most 3.8 minutes at a time in the first 16 hours of 2026-10-20. [docs/orchestrators.md](docs/orchestrators.md), "Builds clear BEAST".
- **No Unity compile beside a timed bench leg** (w1628; lothsahn: "Won't builds use a ton of cpu and invalidate runs?"): a sandbox editor's compiles, imports and test runs over the Unity MCP bridge take a shared ticket in the machine's bench queue and wait their turn (`Queued (w1628)` with the place kept when a leg runs long), a batch Unity started straight from the shell is refused with the `unity-slot run` to use, and a checkout from before w1615 queues with another sandbox's copy of the queue script. [docs/unity-lifecycle.md](docs/unity-lifecycle.md), "The bench queue".

- **Two tests that failed in full-suite runs on Windows are fixed at their cause** (w3337, asked by Ben): the pair-run tests (w890, w1945) wrote a fresh git read into the portal's copy only, so the daemon's first report, about 30 s after it starts, replaced it with its own older read and the release pass held the sandbox; their read is now the daemon's own, reported. The file-attachment link case made a file symlink, which Windows refuses without developer mode (EPERM); it is a junction now.
- **A daemon no longer leaves a keep-awake holder behind** (w3337): one started after the daemon stopped was never killed, and since it waits for the daemon's process while holding that process open, `server/machines.test.ts` never ended (two full suites hung over an hour). The daemon starts none once stopped, and the holder no longer keeps its process alive. Sandbox creation also sets git-lfs's config key under the clone lock, so a parallel worktree add no longer fails reading `.git/config` on Windows.

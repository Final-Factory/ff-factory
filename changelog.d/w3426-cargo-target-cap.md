- **A worker's Rust build folder stays under 8 GB** (w3426, asked by Ben): cargo never deletes what an older build left, so one FFU worker's `ffu/target` on BEAST had grown to 23.6 GB while a fresh one is about 5.8 GB, and a drive with room never reached the low-disk pass that prunes it. Now, on every clean-up pass, a worker's cargo target over 8 GB (`cargoTargetCapGB`) is trimmed once no cargo, rustc or linker runs in that worker, no process uses the folder and nothing in it was written for 15 minutes: only its `debug/incremental` cache when that brings it under 8 GB (the next build takes about 52 s instead of 30 s, measured), otherwise the whole folder (a 3.5 min rebuild, measured on BEAST).

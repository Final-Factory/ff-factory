- **A close closes a request for everyone on it, and a hand-off is its own option** (w1511, asked by lothsahn: "Why can't I close things for Ben? We should be able to close each other's stuff"; then: "It shouldn't be open for one person and closed for another"). `update_work close` on a request with several requesters used to take only the closer off it unless they had filed it (w1505: "lothsahn is off w1505; it carries on for ben"). Now every close, done or cancelled, closes the request for all its requesters and tells the others who closed it and why, and so does a conditional close ("close it once #1314 merges"). To pass a request on and keep it open, `update_work` takes `assign_to` (a user id or name): the receiver takes the sender's place and is told, and the sender is off it. Deploy: the portal restarts; each orchestrator's tool list changes (update_work gains `assign_to` and a shorter description), so running orchestrators see it on their next start. Tests: `server/orchestrators.test.ts`.

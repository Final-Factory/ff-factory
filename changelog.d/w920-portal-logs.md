- **Workers read the portal's own logs, read-only** (w920, lothsahn: "Let's make workers able to see the portal log somehow.  It should be read only"). New worker tool `mcp__machine__portal_logs`: the portal's journal (`journal`, `portal`, `updater`, `health`), any computer's clean-up passes (`cleanup`, with `machine`) and the update hand-off files (`update_result`, `update_verified`, `update_prepared`, `update_verifying`, `machine_rollout`, `unit_watchdog`), paged like `ffbox_activity`'s `logs` view (`since`, `until`, `grep`, `regex`, `limit`, `offset`; 48,000 characters a page). A fixed list of sources: `state.json`, the vault, logins, sessions, keys, queued messages and uploads are not on it, and a worker's text never becomes a path or a command. Every line is redacted on the portal before it is filtered (the existing `redactSecrets` plus Authorization and cookie headers, bearer tokens, URL passwords, `password=`/`"token":` values and JWTs), and a line that still looks like a secret is left out and counted. The worker brief tells workers to check these logs instead of inferring what the portal did. Needs a portal deploy; the journal also needs the guest install's new `fff-portal.service.d/20-journal.conf` (`SupplementaryGroups=systemd-journal` for the server's service, written only where the group exists), which the same update installs; until it does, the journal sources say the account cannot read it and the others work. docs/portal-logs.md.
